# План переноса ZenMoney Skill в MCP

Исходный контракт: установленный `zenmoney-skill` на ревизии `d1f4c417351bbb0b7ed8cbc798412abee86b2b22`. Его 28 обработчиков и финансовые тесты являются базой для сравнения. До переноса базовый набор прошёл: 390 тестов и 85 подтестов.

## Архитектура

1. Самостоятельный Python-проект содержит финансовое ядро `scripts/zenmoney` и MCP-адаптер. MCP вызывает обработчики напрямую, без запуска skill CLI.
2. MCP публикует те же 28 имён инструментов. Проверка аргументов, расчёты Plans и Analytics, классификация переводов, бюджетов и напоминаний, а также коды финансовых ошибок остаются в ядре.
3. Каждый вызов, которому нужны данные ZenMoney, получает свежий полный снимок через публичный `POST /v8/diff/` с `serverTimestamp: 0`. Снимок живёт только во время вызова; файловая ветка `.cache.json` и старый CLI удалены из проекта. `suggest` вызывает `/v8/suggest/`. После записи остаётся независимая принудительная загрузка затронутых типов сущностей и проверка полей/удаления.
4. Вызовы внутри процесса сериализуются, поскольку финансовое ядро использует глобальное состояние. Локальные настройки хранятся вне исходного кода в каталоге, заданном `ZENMONEY_STATE_DIR`. Токен: `ZENMONEY_TOKEN`, затем приватный `config.json` как совместимый резервный источник.
5. Для уменьшения контекста модели MCP выдаёт компактные ответы на объёмные чтения и предоставляет полную форму по явному параметру `response_mode=full`. Полный финансовый расчёт выполняется до сокращения представления. Ошибки не сокращаются. Список инструментов стабилен и может кэшироваться клиентом; финансовые результаты не кэшируются между вызовами.
6. Локальный транспорт — `stdio`. Удалённый — Streamable HTTP по HTTPS. Удалённый вход требует OAuth 2.1 Authorization Code + PKCE S256: Protected Resource Metadata, `WWW-Authenticate`, авторизационный сервер с discovery, CIMD или DCR, проверка JWT (`iss`, `aud`, срок, субъект, scopes) на каждом запросе. ZenMoney-токен остаётся только на сервере. Scopes разделяют чтение и запись.
7. Все изменяющие инструменты требуют явный `confirm_write=true` до сетевого вызова или локальной записи. Это дополнительный MCP-предохранитель; остальные аргументы и доменная логика прежние.

## Порядок

1. Перенести только отслеживаемые исходники и тесты. Не переносить `.cache.json`, `config.json`, `.mcp.json`, `PROFILE.md`, токены и персональные данные.
2. Перевести загрузку данных на полный снимок на каждый вызов и вынести локальные настройки из каталога проекта.
3. Реализовать MCP-каталог, схемы, маршрутизацию, компактное представление и `confirm_write`.
4. Реализовать защищённый удалённый endpoint; подготовить проверку discovery/401/scopes/JWT и инструкции для совместимого OAuth-провайдера.
5. Прогнать регрессию финансового ядра, контрактные MCP-тесты, тесты отсутствия файлового кэша и безопасности удалённого входа. Сделать тестовый MCP handshake и `tools/list`; живые финансовые записи не использовать в тестах.

## Критерии готовности

- `tools/list` содержит все 28 исходных имён с описаниями и параметрами.
- В полной форме результаты инструментов совпадают с исходным ядром на одинаковом снимке и настройках, кроме согласованной замены постоянного кэша на свежий снимок.
- В производственном коде нет файлового API-кэша; каждый вызов с данными получает `serverTimestamp: 0`.
- Ошибка доступа, некорректный курс, неоднозначная категория, семейный профиль, unsupported расчёт и неподтверждённая запись сохраняют явный исход.
- Записи без `confirm_write=true` не доходят до ZenMoney и не меняют настройки.
- Удалённый запрос без валидного OAuth-токена и нужного scope отклоняется до MCP-обработчика.
- Проект не содержит секретов и приватного финансового снимка.
